## 1. Executive Summary & Objective

In Android 10 through Android 16, Android platform security policies (`AudioPolicyService` buffer zeroing and `CAPTURE_AUDIO_OUTPUT` protection) prevent third-party applications from directly intercepting cellular telephony baseband audio streams. 

However, users frequently want access to their recorded cellular conversations alongside their in-app VoIP calls within a single, elegant interface.

This technical proposal investigates two major integration pillars:
1. **Legal, Zero-Hack OEM Native Recording Ingestion:** Automatically or interactively importing high-fidelity, two-way cellular recordings generated by manufacturer native dialers via standard, documented Android integration APIs:
   - **Storage Access Framework (SAF)** with persistable folder tree permissions (`ACTION_OPEN_DOCUMENT_TREE`).
   - **System Content Sharing (`ACTION_SEND`)** allowing 1-tap import from native recorders.
   - **Standard MediaStore Ingestion** for publicly discoverable audio collections.
2. **Unified TWING Recording Architecture:** Enhancing TWING's existing recording library, SQLite database, and playback interface to seamlessly manage both:
   - In-app **TWING Voice (VoIP / WebRTC)** recordings (100% two-way HD audio).
   - **Imported OEM Cellular Recordings** (matched automatically to caller contact name, phone number, and timestamp).

## 4. Ingestion Architecture: Three Legal Integration Pathways

```
┌─────────────────────────────────────────────────────────────────────────────────────────┐
│                               TWING Recording Library                                   │
└──────────────────────────────────────────┬──────────────────────────────────────────────┘
                                           │
         ┌─────────────────────────────────┼────────────────────────────────┐
         ▼                                 ▼                                ▼
┌─────────────────────────┐   ┌──────────────────────────┐   ┌────────────────────────────┐
│ Pathway A: SAF Auto-Sync│   │ Pathway B: System Share  │   │ Pathway C: In-App VoIP HD  │
│ (One-Time Folder Grant) │   │ (ACTION_SEND Receiver)   │   │ (Direct WebRTC / Twilio)   │
├─────────────────────────┤   ├──────────────────────────┤   ├────────────────────────────┤
│ • ACTION_OPEN_DOC_TREE  │   │ • Native Recorder Share  │   │ • In-app Voice Calling     │
│ • takePersistableUri    │   │ • Google Dialer Share    │   │ • AudioRecord + AAC stream │
│ • Auto-scan on call end │   │ • Immediate import       │   │ • 100% Two-Way HD audio    │
│ • Background copy to DB │   │ • Automatic metadata     │   │ • AUDIO_CAPTURE_CONFIRMED  │
└─────────────────────────┘   └──────────────────────────┘   └────────────────────────────┘
```

### Pathway A: Storage Access Framework (SAF) Folder Link (Recommended for Automatic Sync)
1. **User Onboarding Flow:**
   - In Settings -> Call Recording or Recordings Tab, show a card:
     *"Link Native Call Recording Folder for Automatic Cellular Sync"*.
   - When tapped, TWING opens the system folder picker pre-hinted to the device's default OEM folder:
     ```java
     Intent intent = new Intent(Intent.ACTION_OPEN_DOCUMENT_TREE);
     if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
         Uri initialUri = getRecommendedOemFolderUri();
         intent.putExtra(DocumentsContract.EXTRA_INITIAL_URI, initialUri);
     }
     startActivityForResult(intent, REQUEST_CODE_SAF_FOLDER);
     ```
   - On result, TWING saves the persistable permission:
     ```java
     context.getContentResolver().takePersistableUriPermission(
         treeUri, 
         Intent.FLAG_GRANT_READ_URI_PERMISSION
     );
     PreferencesHelper.setRecordingFolderTreeUri(context, treeUri.toString());
     ```
2. **Automatic Call-End Ingestion:**
   - When `CallStateReceiver` receives `CALL_STATE_IDLE`, an asynchronous worker scans the linked `DocumentFile` tree for files modified in the last 2 minutes.
   - It matches the audio file to the latest `CallLog` entry (timestamp, phone number).
   - Copies the file securely into TWING's private sandbox (`getFilesDir()/CallRecordings/`).
   - Inserts the record into SQLite with `status = "COMPLETED"`, `call_type = "CELLULAR_IMPORTED"`.

### Pathway B: Universal "Share to TWING" Intent Handler (Zero Permissions Needed)
- Add an `intent-filter` for `ACTION_SEND` and `ACTION_SEND_MULTIPLE` with mimeType `audio/*`.
- When a user shares a call recording from **Google Phone, Vivo Recorder, ODialer, Samsung My Files, or WhatsApp**:
  - TWING parses the incoming `content://` URI.
  - Queries `MediaStore` or `OpenableColumns.DISPLAY_NAME` for duration and filename.
  - Automatically matches the caller by parsing the filename or checking recent `CallLog`.
  - Imports the file into TWING with a single tap.

### Pathway C: In-App VoIP Call Recording (Existing & 100% Functional)
- In-app voice calling over WebRTC/Twilio is **unaffected by cellular baseband restrictions**.
- Captures digital uplink and downlink streams in high-definition 128 kbps AAC stereo.
- Flagged with badge `TWING Voice` in the unified library.

## 5. Intelligent Call Matching Algorithm (`RecordingMatcher`)

When an external recording file is imported via SAF or Share Intent:

```
                  OEM Recording Audio File
               (e.g., +919876543210_20261122114500.m4a)
                                 │
                                 ▼
                    ┌─────────────────────────┐
                    │  Extract Telemetry:     │
                    │  1. Filename timestamp  │
                    │  2. File lastModified   │
                    │  3. Filename phone/name │
                    └────────────┬────────────┘
                                 │
                                 ▼
                    ┌─────────────────────────┐
                    │ Query Android CallLog:  │
                    │ Window: FileTime ± 90s  │
                    └────────────┬────────────┘
                                 │
                 ┌───────────────┴───────────────┐
                 ▼                               ▼
       [Matching Call Found]           [No CallLog Match]
                 │                               │
                 ▼                               ▼
   Extract exact Contact Name,       Use parsed phone number 
   Phone Number, Direction           or "Imported Recording"
   (Incoming/Outgoing), and CallId
                 │                               │
                 └───────────────┬───────────────┘
                                 │
                                 ▼
                 Insert into SQLite Database
           Status: "COMPLETED", Source: "OEM_IMPORT"
```

1. **Step 1: Extract Date/Time:** Parse filename using regex patterns for Vivo (`_yyyyMMddHHmmss`), OnePlus (`_yyyyMMddHHmmss`), Samsung (`_yyyyMMdd_HHmmss`), Xiaomi (`(yyyyMMddHHmmss)`), or fallback to `file.lastModified()`.
2. **Step 2: Query System CallLog:** Search `CallLog.Calls` for any call with `date` within ±90 seconds of the recording time.
3. **Step 3: Resolve Participant Info:**
   - Phone Number & Normalized E.164 number.
   - Contact Name from Android Contacts Provider.
   - Direction: Incoming (↙) vs Outgoing (↗).
   - Exact call duration.
4. **Step 4: Save & Display:** Store with `callType = "CELLULAR_IMPORTED"` and `recordingSource = "OEM_IMPORT_VIVO"` / `"OEM_IMPORT_ONEPLUS"`.

## 8. Implementation Steps & Rollout Strategy

If this proposal is approved, implementation will proceed in 4 phases:

1. **Phase 1: Ingestion Engine & Matching Logic (`OemRecordingImporter` & `RecordingMatcher`)**
   - Create isolated classes to parse OEM directory naming patterns.
   - Implement `CallLog` fuzzy time matching (±90s threshold).
   - Test with simulated and sample OEM files.
2. **Phase 2: Storage Access Framework (SAF) Setup UI**
   - Add "Link Native Call Recording Folder" in Settings and Recordings tab.
   - Pre-select recommended folder based on `Build.MANUFACTURER` (Vivo: `Record/Call`, OnePlus: `Recordings/Call Recordings`, Samsung: `Recordings/Call`).
   - Store persistable URI in `SharedPreferences`.
3. **Phase 3: Universal System Share Receiver (`ACTION_SEND`)**
   - Register `RecordingShareActivity` for `ACTION_SEND` audio.
   - Enables instant sharing from Google Phone, ODialer, or File Manager.
4. **Phase 4: Automatic Call-End Scanning & UI Polish**
   - Wire `CallStateReceiver` to trigger a lightweight background check of the linked SAF folder upon `CALL_STATE_IDLE`.
   - Update `CallRecordAdapter` with distinct visual badges.
   - Run full regression testing across all existing modules.
